# けやきネット キャンセル待ち監視（LINE通知）

世田谷区「けやきネット」を30分おきに自動でチェックします。条件に合う部屋に空きが出たら、LINEで「日付・施設・部屋・空いている時間帯」をお知らせします。動かすのはGitHub Actionsなので、PCは不要です。

## 何をしているか
1. 使用目的「ダンス・軽体操系 → その他ダンス（音量小）」で検索
2. `config.json` に書いた21施設を選んで「次へ進む」
3. 表示開始日をセットして「1ヶ月」表示にし、見張る日付に○か△がある部屋を探す
   - 部屋の条件: **定員100以上** または **150㎡以上** または **どちらも書いていない**
4. その○・△を選んで「次へ進む」。時間帯別の画面で○の時間帯をLINEに送る

- 一度通知したコマは、もう一度は送りません（埋まってから再び空いたら、また送ります）
- 深夜1時〜6時はお休みします（区のサイトに負担をかけないため）

## 見張る日付を変えるには（config.json）
```json
"watch": {
  "weekdays": ["土"],              // 毎週見張る曜日。["土","日"] なども可
  "monthsAhead": 2,                // 何ヶ月後の月末まで見るか（11/12なら1/31まで）
  "dates": ["2026-12-06"],         // 曜日以外で追加したい日
  "excludeDates": ["2026-12-26"]   // 見張らなくていい日
}
```
（`//` から右は説明なので、実際のファイルには書かないでください）
GitHubのアプリやブラウザで `config.json` を開き、鉛筆マークから編集して保存すれば、次の回から反映されます。

## セットアップ

### 1. LINEの通知ボットを用意する
**既にあるボット（オリンピックセンター通知など）を使う場合**は、新しく作らずに次の2つをコピーするだけでOKです。
- 「Messaging API設定」タブの「チャネルアクセストークン（長期）」→ 表示されている値をそのままコピー（**「再発行」は押さない**。押すと今のボットが止まります）
- 「チャネル基本設定」タブの「あなたのユーザーID」

**新しく作る場合（10分）**
1. https://developers.line.biz/console/ にLINEアカウントでログイン
2. プロバイダーを作成（名前は何でもOK）→「Messaging API」チャネルを作成
   - 画面の案内でLINE公式アカウントを作る流れになったら、そのまま作成し、LINE Official Account Manager の設定で Messaging API を有効にする
3. チャネルの「Messaging API設定」タブ
   - QRコードを読んで、ボットを**友だち追加**
   - 一番下の「チャネルアクセストークン（長期）」を**発行**してコピー → これが `LINE_CHANNEL_ACCESS_TOKEN`
4. 「チャネル基本設定」タブの一番下「あなたのユーザーID」（Uから始まる）をコピー → これが `LINE_USER_ID`

※ 無料プランは月200通まで。1回のチェックで見つかった空きは1通にまとめて送ります。

### 2. GitHubにリポジトリを作る
1. 新しいリポジトリを作成。**Publicを推奨**します（Privateだと、30分おきの実行で無料枠の月2,000分を超えます）。トークンは次の手順で「Secrets」に入れるので、Publicでも公開されません
2. このフォルダの中身を全部アップロード（`.github` フォルダも忘れずに）

### 3. Secretsを登録
Settings → Secrets and variables → Actions → New repository secret
- `LINE_CHANNEL_ACCESS_TOKEN`
- `LINE_USER_ID`

### 4. 動作確認
Actions タブ →「けやきネット空き監視」→ Run workflow
- まず **test_notify にチェックを入れて**実行 → LINEに「テスト通知です」が届けばOK
- 次に **チェックを外して**（debugはオンのまま）実行 → ログに「見張る日付」「空き候補」が出れば成功です
- 失敗したら、ログの赤い行（❌）と、実行結果ページ下の `debug-screens`（各画面のスクショ）を見れば原因が分かります

あとは30分おきに自動で動きます。

## 注意
- 60日間リポジトリに更新がないと、GitHubが定期実行を自動で止めます（Actionsタブから再開できます）
- けやきネットの画面が変わると動かなくなることがあります。その場合はエラーがLINEに届きます（12時間に1回まで）

# 文京区（文の京 施設予約ねっと）の空き監視

同じリポジトリ・同じLINEボットで、文京区も30分おきに見張ります（:18と:48に実行）。設定は `bunkyo/config.json`。

1. 利用目的「体操・ダンス → ダンス」で検索
2. `bunkyo/config.json` の16施設にチェックして「次へ進む」
3. 「1ヶ月」表示で、見張る日付（2ヶ月後の月末までの毎週土曜）に○か△がある部屋を探す
   - 部屋の条件: **定員80人以上** または **定員の表記なし**
4. その○・△を選んで「次へ進む」。時間帯別の画面で○の時間帯（午前・午後など）をLINEに送る
   - サイトの反応が遅い（1画面1〜2分）ので、時間帯の確認は1回につき各月10コマまで。記号が変わったコマを優先し、残りは順番に確認します（全コマ1時間に1回程度は確認されます）

- 部屋の条件: 広さが `bunkyo/rooms.json`（練習場所調査シート・区の施設案内より）にある部屋は **150㎡以上**（`roomFilter.minArea`）。広さ不明の部屋は従来どおり **定員80以上か定員表記なし**。通知には広さ（㎡）を表示します
- 特例で必ず見張る部屋は `roomFilter.includeRoomWords` に「施設名+部屋名」で書きます（今は大塚地域活動センター多目的室A+B）

動作確認: Actions タブ →「文京区 空き監視」→ Run workflow（使い方は世田谷と同じ）。失敗したら `debug-screens-bunkyo` のスクショを見てください。

# 新宿区（しせつよやく）の空き監視

同じリポジトリ・同じLINEボットで、新宿区も30分おきに見張ります（:24と:54に実行）。設定は `shinjuku/config.json`。

1. 「新宿区全域(すべて)」×「ダンス（社交ダンス以外）」と「ダンス・健康体操」の2通りで検索
2. 出てきた館・施設（部屋）のうち **150㎡以上** または **広さ不明** の部屋を順番に開き、見張る日付に「空き」があるコマを探す
   - 予約サイトには広さが出ないので、`shinjuku/rooms.json` に部屋ごとの広さ(㎡)を入れてあります（区の資料・施設サイトより）。ここに載っていない部屋は「広さ不明」として監視します
3. 新しく空いたコマを「日付・館・部屋・時間」でLINEに送る（続きのコマは「9:00〜11:55」のようにまとめます）

- 見張る日付の書き方は世田谷と同じ（`watch`）。検索する目的は `purposes` に、サイトの「何をする」の表記どおりに書きます
- 広さの基準は `roomFilter.minArea`、広さ不明を含めるかは `roomFilter.includeUnlabeled` で変えられます
- それでも監視したくない部屋は `excludeRoomWords` に部屋名の一部を書くと外せます（例: `["和室", "学習室"]`）
- 「一般開放」「受付期間外」「休館日」は通知しません

動作確認: Actions タブ →「新宿区 空き監視」→ Run workflow。ログに部屋ごとの空き数と通知文のプレビューが出ます。

# 新宿区 地域センター（しせつよやく 地域センター版）の空き監視

新宿区には予約サイトがもう1つ（地域センター用: https://www.shinjuku.eprs.jp/chiiki/web/index.jsp ）あり、こちらも同じ仕組みで30分おきに見張ります（:06と:36に実行）。プログラムは新宿区版と共通で、`SITE=chiiki` のときに `shinjuku/config-chiiki.json` と `shinjuku/rooms-chiiki.json` を使います。

- 「新宿区立地域センター(すべて)」×「ダンス（軽スポーツ）」で検索
- **150㎡以上** または **広さ不明** の部屋だけを監視。広さは `rooms-chiiki.json`（区の利用案内・使用料一覧より）
- 広さ不明の部屋でも、部屋名の定員（例「バラＡ（３０）」）が `minCapacityIfUnknown`（80）未満なら小部屋として外します
- 通知の時間帯は `labelTimes` で「夜間1 → 17:30〜19:30」のように時刻にし、続きの区分はまとめます

動作確認: Actions タブ →「新宿区 地域センター 空き監視」→ Run workflow（notify_all にチェックで今の空きを全部送信）。

# 板橋区（ITAリザーブ）の空き監視

同じリポジトリ・同じLINEボットで、板橋区も30分おきに見張ります（:12と:42に実行）。設定は `itabashi/config.json`。

1. 「空き照会のみ」で入り、利用目的から2通りで検索（`searches`）
   - 芸術・文化・趣味・教養 → ダンス・バレエ等
   - スポーツ（屋内） → ダンス・バレエ等
2. 「全て選択する」→「次に進む」で出る表を、土曜（と祝日）だけに絞って表示し、見張る日付の○を探す
   - 2つの検索で同じ部屋が出ても、通知は1回だけです
3. 部屋の条件: **150㎡以上** または **広さ不明** の部屋が対象（広さ不明でも定員100名未満の小部屋は外す: `minCapacityIfUnknown`）
   - 予約サイトには定員しか出ないので、広さは `itabashi/rooms.json`（練習場所調査シートより）から入れています
   - 監視したくない部屋は `excludeRoomWords` に部屋名の一部を書くと外せます
4. 新しく空いたコマを「日付・部屋（広さ・定員）・時間帯」でLINEに送る
   - 初めて動いたときは今ある空きを記録するだけで、2回目から新しく空いた分を送ります

動作確認: Actions タブ →「板橋区 空き監視」→ Run workflow（debug オンでログに全部屋の一覧（◎が監視対象）と通知文のプレビュー、notify_all で今の空きを全部送信）。

# YANAGIBA（チームのアプリ）との連携

YANAGIBAの施設予約にある「まだ施設が取れていない日」（東京の練習）も、各区の監視で一緒に見張ります（`yanagiba.mjs`）。

- 見る日付: いつもの土曜 ＋ まだ取れていない日（各区の `watch.monthsAhead` の範囲まで）
- 部屋の広さ（まだ取れていない日）: **土日祝は150㎡以上、平日は100㎡以上**。広さ不明の部屋は各区のいつもの条件
- 練習の時間に重なる空きを、アプリの施設予約の画面に出し、新しい空きはスタッフにお知らせ（プッシュ通知）。LINEにも送ります
- 必要な設定: GitHub の Secrets に `YANAGIBA_SECRET`（アプリのデータベースにある合言葉）。ないときは連携せず、今までどおり動きます

# 品川区（品川区施設予約システム）の空き監視

新宿区と同じ「しせつよやく」なので、新宿区の仕組みで動かしています（`SITE=shinagawa`、設定は `shinjuku/config-shinagawa.json`）。

- どこで: 「荏原地区(すべて)」「大井地区(すべて)」など、地区ごとの「(すべて)」をぜんぶ順に（`"areas": "all"`）
- 何をする: ダンス
- 部屋の条件: 150㎡以上か広さ不明（平日のYANAGIBAのまだ取れていない日は100㎡以上も）。広さは `shinjuku/rooms-shinagawa.json`（練習場所調査シート(品川区)より）。託児室は除外
- 表の区分（午前・午後・夜間）は `labelTimes` で時刻にします。学校は時刻がわからないので区分名のまま
- 初めて動いたときは今ある空きを記録するだけで、2回目から新しく空いた分を送ります
- 動かす時刻: YANAGIBA の Supabase から毎時9分と39分
